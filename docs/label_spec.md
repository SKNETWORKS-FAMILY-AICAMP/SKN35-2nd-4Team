# 라벨 스펙 (Rev.4 4계층 이탈 라벨 + 원인 태그)

이 문서는 `src/features/labels.py`(L1~L3, C 담당)와 `src/models/reason.py`
(원인 태그, C 담당)에 이미 구현된 라벨 정의를 팀 전체가 참고할 수 있게
정리한 것이다. 코드가 최종 진실(source of truth)이고, 이 문서는 그 요약이다
— 코드와 문서가 어긋나면 코드를 따른다.

## 설계 원칙

1. **관측 가능성에 따라 층을 나눈다.** 확정적으로 관측되는 것(같은 팀 소속
   여부)과 추정치(부상 연관성, 방출 vs FA 구분)를 절대 섞지 않는다.
2. **부상·은퇴 같은 미관측 해석을 확정 라벨로 저장하지 않는다.** 부상은
   L1~L3 라벨을 바꾸는 데 쓰지 않고, `reason.py`의 별도 "원인 태그"(약지도
   학습 추정치)로만 다룬다.
3. **선수가 떠날 위험과 구단이 내보내는 정책을 섞지 않는다.** `y_departed`를
   그대로 이탈위험 예측 타깃으로 쓰면 구단이 결정한 방출까지 "선수 위험"으로
   학습되는 순환논리가 생긴다 — 그래서 `y_core_departed`가 따로 있다.

## L1 — `y_departed` (이탈 여부)

**정의**: 다음 시즌에도 같은 `franch_id`에 소속되는가. `season < data_end_year`
인 행만 판정 가능하고(다음 시즌 데이터가 있어야 함), 그 시즌이 관측 데이터의
마지막 시즌이면 결측(censored) 처리한다.

- `0.0` = 잔류 (다음 시즌 같은 franch_id)
- `1.0` = 이탈 (다음 시즌 다른 franch_id 또는 리그 기록 없음)
- `NaN` = 아직 판정 불가 (마지막 관측 시즌)

## L2 — `y_path` (관측 경로, 이탈자에게만)

이탈자(`y_departed == 1`)에게만 부여. 잔류자는 항상 `NaN`.

| 값 | 조건 |
|---|---|
| `trade` | 이번 시즌 안에 이미 스틴트가 2개 이상(`n_stint >= 2`) — 시즌 중 팀 이동을 실제로 겪음 |
| `offseason_move` | 트레이드가 아니고, 다음 시즌 리그 기록이 있음(다른 팀으로) |
| `league_exit` | 다음 시즌 리그 기록 자체가 없음 |

**한계(팀 리뷰에서 합의된 사항)**: Lahman에는 공식 Transactions 테이블이
없어 "trade"를 직접 확인할 방법이 없다. `n_stint >= 2`는 "시즌 중 팀을
옮긴 적이 있다"는 관측 사실의 대리 지표(proxy)이지, 그 이동이 진짜
트레이드였는지(vs 웨이버 등)를 확정하지는 않는다.

## L2b — `y_fa_release` (FA·방출 세부 분류, offseason_move에만)

`y_path == "offseason_move"`인 행에만 부여. 그 외에는 항상 `NaN`. **FA와
방출을 하나의 클래스로 합치지 않는다** — 의사결정 성격이 정반대이기 때문
(선수가 나가고 싶어서 vs 구단이 내보내고 싶어서).

| 값 | 조건 |
|---|---|
| `release_certain` | `exp < 6` (서비스 타임 규칙상 FA 자격이 제도적으로 불가능 → 방출 확정) |
| `fa_est` | `exp >= 6`이고 추정상 FA 가능성이 높음 |
| `release_est` | `exp >= 6`이지만 추정상 방출 가능성이 높음 |

`fa_est`/`release_est`는 **추정치**다 — `release_certain`만 서비스 타임이라는
제도적 규칙으로 확정된다(한쪽 방향으로만 확정되는 비대칭 규칙).

## L3 — `y_returned` (복귀 여부, league_exit에만)

`y_path == "league_exit"`인 행에만 부여. `LabelConfig.return_offsets`(기본
`(2, 3)`시즌 뒤)안에 리그 기록이 다시 나타나면 복귀로 본다.

- `1.0` = 지정된 기간 안에 복귀 관측됨
- `0.0` = 지정된 기간이 다 지나도록(`season + max(return_offsets) <= data_end_year`) 복귀 안 됨 — 확정적으로 "안 돌아옴"
- `NaN` = 아직 그 기간이 다 지나지 않아 판정 불가

## L1' — `y_core_departed` (핵심 이탈위험 타깃)

`departure.py` 등 "선수가 떠날 위험"을 예측하는 모델은 **`y_departed`가 아니라
반드시 이 컬럼을 써야 한다.** `release_certain`(구단이 방출 확정) 행만 결측
처리하고, 나머지는 `y_departed`와 동일하다. 이유는 위 "설계 원칙 3" 참고.

```python
confirmed_release = y_fa_release == "release_certain"
y_core_departed = y_departed.where(~confirmed_release, NaN)
```

## y_next_score (회귀 타깃, D 담당)

다음 시즌 `overall_score`. 위 라벨들과 무관한 별도 회귀 타깃 — 이탈 여부가
아니라 "얼마나 잘할 것인가"를 예측할 때 쓴다. 다음 시즌 기록이 없으면(은퇴·
이탈 등) `NaN`.

## 원인 태그 (reason.py) — 별도 체계, 정답 라벨이 아님

`primary_reason`/`reason_tags`는 **위 L1~L3 라벨을 바꾸지 않는다.** 이미
확정된 이탈 사실에 대해 "왜 그랬을 가능성이 있는지"를 사후에 약지도학습으로
추정하는 **보조 설명**이다. 서비스 화면에는 반드시 "연관 요인" 또는
"모델 추정"으로 표시하고, "~때문에 이탈함"처럼 인과관계를 단정하지 않는다.

**적용 범위 (2026-08-27 팀 결정)**: 원래 설계는 원인 태그를 방출·은퇴에만
붙이는 것이었으나, 부상이 트레이드·FA 이적의 배경 요인으로도 작용할 수
있다고 보고 **전체 이탈 유형(trade/offseason_move/league_exit)으로 확장**했다.

### 태그 종류

| 태그 | 판정 기준(훈련 구간 분위수로 계산) |
|---|---|
| `injury_associated` | 부상 위험 점수가 훈련구간 상위 분위수 초과 |
| `performance_decline` | 전력 점수 하락폭 또는 출전비중 하락이 기준 초과 |
| `career_stage` | 나이·경력이 훈련구간 상위 분위수 초과(베테랑) |
| `mixed` | 위 중 2개 이상 동시 해당 |
| `unknown` | 위 어느 것도 해당 안 됨 — "현재 데이터로 판단 어려움"으로 표시 |

### 임계값은 훈련 구간에서만 계산한다

`ReasonConfig.train_end_year`(기본 2021) 이하 데이터로만 분위수(부상 위험
75%, 성적하락 25%, 나이/경력 75% 등)를 계산한다 — 검증/테스트 구간 정보가
임계값 계산에 새어 들어가지 않게 하기 위함.

### 부상 데이터의 확실성 비대칭

`had_injury=1`(IL 등재 기록 확인됨)은 확정적이지만, `had_injury=0`은
"부상 없음"이 아니라 "현재 데이터에서 IL 기록이 관측 안 됨"이다(ID 매칭
실패 등 포함 가능) — `injury_record_matched` 컬럼으로 이 구분을 유지한다.

## 알려진 구조적 한계

- **트레이드가 전체 이탈의 ~6%뿐**이라 L2 분류(특히 trade 클래스) 성능에
  구조적 한계가 있다 — 클래스 불균형이 심함.
- **전력 예측(D)은 리그 잔류 선수만으로 학습**되어 생존 편향이 있다 —
  이탈한 선수의 "만약 남았다면"의 전력은 알 수 없다.
- **원인 태그는 규칙 기반 약지도학습**이라, `reason_rf`/`reason_mlp`의
  accuracy는 "실제 이탈 원인을 맞췄는가"가 아니라 "이 규칙을 재현했는가"를
  재는 것에 더 가깝다 — 천장이 규칙 품질에 묶여 있다.
